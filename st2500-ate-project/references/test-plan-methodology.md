# 从器件手册到测试方案

## 一、通用流程

```
① 读手册 → ② 提限值（逐条标表号）→ ③ 核资源可行性
   → ④ 设计测试项矩阵 → ⑤ 讨论确认 → ⑥ 写工程 → ⑦ 交叉校验
```

### ② 提限值——每条都要能指到表号

必须提取的项：

| 类别 | 内容 |
|---|---|
| 供电 | VCC 范围、绝对最大额定值 |
| 输入 | VIH(min)、VIL(max)、II(漏电流) |
| 输出 | VOH(min)、VOL(max)、IO 负载条件 |
| 电源 | ICC / IDD |
| 动态 | tpd、tr/tf（**需确认 ATE 能否测**） |
| 封装 | 全部可选封装（**查有没有 DIP**） |
| 真值表 | 完整逻辑表 |
| 特殊用法 | 如"可作 8 选 1 数据分配器" |

**限值必须随 VCC 变化**，手册通常给 2.0/4.5/6.0V 三档。做教学案例取
4.5V（5V 系统最差角）；量产要多角压测。

### ③ 核资源可行性

```
所需 DIO 数  vs  板卡通道数
所需 DPS 数  vs  DPS 数量
需要的模块（TMU?） vs 机台是否有
封装类型 vs 接口板 socket 形式
```

**封装坑**：手册 Table 1 常只给 SO/TSSOP/QFN，**没有 DIP**。
而通用接口板是万用板 + DIP socket → 需要 **SO16→DIP16 转接板**。

### ④ 测试项矩阵

| 序 | 测试项 | 资源 | 限值来源 | 备注 |
|---|---|---|---|---|
| 0 | OSN | PPMU×N | 经验值 | 开路/短路检测（负向） |
| 1 | OSP | PPMU×N | 经验值 | 开路/短路检测（正向） |
| 2 | IIL | PPMU×输入脚 | Table N | 输入漏电流 |
| 3 | **VIH** | DIO + pinlevel | Table N | **输入门限** |
| 4 | **VIL** | DIO + pinlevel | Table N | **输入门限** |
| 5 | VOH | DIO + PPMU | Table N | 输出高电平 |
| 6 | VOL | DIO + PPMU | Table N | 输出低电平 |
| 7 | IDD | DPS | Table N | 静态电源电流 |
| 8 | FUNC | DIO Pattern | 真值表 | 功能/译码 |
| 9 | SetPassBin | — | — | 置 Pass Bin |

**VIH/VIL 是最容易被漏的**，但它是数字 IC 的核心参数——与 VOH/VOL 是一对
镜像概念：

- VOH/VOL：芯片**输出**的电压有多高/多低
- **VIH/VIL：芯片输入的门限——把输入脚加到多高，它还认这是"1"？多低还认这是"0"？**

噪声容限 = VOH − VIH。

## 二、VIH/VIL 的测法（pinlevel 二分搜索）

### 原理

`SetVih(v)` 设的是"**当这个脚驱动高时，电平是多少**"——它是**电平字典**，
不是当前电平。Pattern 里写 `1` 用 `SetVih` 的值，写 `0` 用 `SetVil` 的值。

所以测 VIH 就是：`SetVih(mid)` → 跑 pattern → 看译码还对不对。
对了说明 mid 够高（是 1），错了说明 mid 还没到（被当成 0）。

**这个方法不需要 PPMU，纯 DIO 就能做。**

### 前提：被测脚必须单独成组

因为 `SetVih` 是组级设置，要只给 A0 施 3.15V 而其它脚保持 4.5V，
A0 必须单独成组：

```
ADDR0       = A0                    → SetVih(3.15)
ADDR_OTHERS = A1,A2,E1,E2,E3        → SetVih(4.5)
OSPINS      = Y0~Y7                 → SetVoh/SetVol 决定比较门限
```

### 判据设计（关键技巧）

固定激励让 **A2A1A0=000 → Y0 恒为 L、其余恒 H**，
这样"被测脚被认成 0 还是 1"都能唯一判定——两种情况期望值不同，不会混淆。

例（测 A0 的 VIH）：

| Pattern 写 | 含义 | 期望 |
|---|---|---|
| `A0=1, E1=0,E2=0,E3=1, A1=0,A2=0` | A0 是高 | Y0=L（选中），其余 H |
| `A0=0, ...` | A0 是低 | Y0=H（不选中），其余 H |

### 三种做法

| 做法 | 内容 | 成本 | 建议 |
|---|---|---|---|
| **甲** 二分搜索 | 找实测翻转点，12 次迭代 | 6脚×3角×2×12 = **432 次运行** | 真正的参数表征，第一版太重 |
| **乙** 规格点验证 | 直接施加 3.15V / 1.35V，验证译码仍正确 | **36 次判定**，很快 | **必做**，符合 JEDEC 规范精神 |
| **丙** 规格点±100mV | 乙 + 边界余量 | 108 次 | 折中，能看出接近失效的器件 |

**建议先做乙**，有余力再叠甲。

## 三、低有效器件的特殊处理

74HC138 / 74HCxx 系列输出**低有效**（inverting），8 路输出**互斥**。

### VOH/VOL 激励与常规相反

| 测什么 | 需要什么激励 |
|---|---|
| **VOL** | 让该路**被选中**（地址对准它）→ 输出低 |
| **VOH** | 让该路**不被选中**（如 E1=H 使全输出 HIGH）→ 输出高 |

这跟 CD4511（高有效）完全不同，需要新设计。

### 功能测试必须同时比较全部输出

任何时刻至多 1 个输出为 LOW、其余 7 个为 HIGH。
所以 pattern 必须**每行 8 个全比较**——只查选中的那一位，输出脚间短路/浮空
测不出来。

`.tim` 里要给 8 个输出各定义 `H`/`L`/`X` 三个 WFC 槽位。

## 四、MCU 类器件（HK32F031 案例）

MCU 的测试项不只是判对错，而是**用 PPMU 测电流**：

| Pattern | 作用 |
|---|---|
| `PASSCODE` | 正确的密码序列，让芯片进入目标状态 |
| `VOPDPAT` / `VOPUPAT` | 配置成下拉/上拉，再用 PPMU 测电流 |
| `PLL` | 配合 `repeat_inf` + TMU 测频（本机 ST2500 无 TMU，跳过） |
| `ROM` / `ADCF` | 读 ROM 内容、ADC 采样 |

PPMU 测上下拉电流的逻辑：
1. 跑 pattern 把芯片配到"某脚被内部上拉/下拉"的状态
2. 断开该脚的 DIO 驱动
3. PPMU 施加电压测电流 → 与手册的 IOH/IOL 限值比

### PLL / 振荡器测频的标准套路

```
repeat_inf  +  SetHoldExit()  +  TMU
```

让 DUT 自由振荡，TMU 测到稳定频率后再主动放行退出无限循环。
**ST2500 无 TMU，此项跳过。**

## 五、教学案例的取舍

| 维度 | 教学版 | 量产版 |
|---|---|---|
| 电压角 | 1 个（4.5V） | 3 个（2.0/4.5/6.0V） |
| 温度 | 室温 | 全温度点 |
| 动态延迟 | 通常不测 | 必测（需 TMU 或 DGT） |
| 功能覆盖 | 核心译码 | 全真值表 + demux 等特殊模式 |
| VIH/VIL | 规格点验证（乙） | 二分搜索（甲）做表征 |
| 迭代次数 | 12 次（二分） | 可调到 6 次（精度 ~70mV，够用） |

## 六、讨论时该问用户的 5 个点

1. **教学还是量产？** 直接影响复杂度
2. **哪种型号？** 74HC138 vs 74HCT138 限值差很多（HCT 是 TTL 电平，VIH≥2.0V，
   VCC 只有 4.5~5.5V）
3. **动态延迟测不测？** ST2500 无 TMU，理论上要靠 DGT 方案
4. **特殊模式测不测？** 如手册提到的 demux 模式
5. **封装怎么接？** SO16→DIP16 转接板 / 贴片打线 / 新做测试板
   ——**这一条最要紧，不解决整个方案落不了地**
