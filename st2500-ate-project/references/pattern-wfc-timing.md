# Pattern / WFC / 时序设计方法论

## 一、翻译链（理解一切的钥匙）

```
Pattern 里写的字符
   ↓ 查 .tim 的 (TimingName, 信号名, WFC槽位名)
实际的边沿序列 (Event, 时刻)
   ↓ 在时间轴上展开
真实波形
```

**字符本身不含任何电平信息。** 必须三者联合查表。

## 二、两套编号体系（最易卡住的点）

`.tim` 表格里同时存在两套独立编号，长得像但各管各的：

| | WFC 列 | Evt0 ~ Evt3 列 |
|---|---|---|
| 是什么 | **槽位的名字**（该信号的第几种波形） | **槽位内部的第几个边沿** |
| 位置 | **行首**，每行一个 | **列头**，固定四列，全表通用 |
| 命名 | 用户自定义（0/1/X/Z/H/L…） | 系统固定，不���改 |
| 数量 | 每信号任意多个 | 每行最多 4 个 |
| 谁能填 | 驱动态可填 U/D/Z；比较态只能填 H/L/X | — |

**"只有 Evt0" ≠ "只有一个槽位"。** Evt0~Evt3 像表格模板印好的四个固定格子，
空格子不是出错，只是这个波形用不到那么多边沿。

### 硬件规则（API 手册第 62 章 `EN_EVENT_MARK` 枚举）

| 事件标记 | 含义 | 数量上限 |
|---------|------|---------|
| `D0`~`D3` | Driver 第 1~4 个 Edge | 驱动最多 **4** 个边沿 |
| `R0` | Compare 的 Edge | 比较只有 **1** 个 |

→ 所以 `L`/`H`/`X` 这类比较槽位**在硬件上不可能有 Evt1**，配了也没意义。
手册原文："替换的 Event 类型组合，最大四个 Event"。

### 实测：编号不要求连续，顺序不影响功能

| 工程 | 信号 | WFC 序列 |
|---|---|---|
| CD4511 | `OUTPUT_PINS` | `L, H, X` |
| HK32F031 | `PA7`（BISTTIMING） | `0, 1, X, Z, L, H` |
| HK32F031 | `PA7`（PLLTIMING） | `0, 1, X, Z, H, L` |

同一个信号在不同 WFT 下 H/L 顺序是反的；编号也可以跳号。
**它只是槽位名，Pattern 里引用哪个名字就找哪个槽位。**

## 三、WFC 字符集 ⊆ 约束（硬约束）

> **Pattern 里的字符必须 ⊆ 对应 (WFT, 信号) 的 WFC 槽位集合。**
> 违反 → 加载 Pattern 时报错。

已对 6 个案例、48 个 pattern、51.7 万行向量做过全量交叉校验，0 违规。

注意：`.tim` 的 `Signal` 列可以写**信号组名**（如 `OUTPUT_PINS`），
组内所有管脚共用一套 WFC 槽位 → 组内各脚能写哪几个字符由组决定。

验证脚本：`scripts/validate_project.py`（检查项 1）。

## 四、课件权威示例（WFT1，Period 100ns）

出自 `2.教学课件/6.课件-数字电路模块功能介绍.pdf` 第 26 页，
该页表格下方配着官方示波器波形图。

| 槽位 | SD1 (数据线) | CLK (时钟线) |
|------|--------------|--------------|
| `0` | `D@0ns` | `D@0ns` |
| `1` | `U@0ns` | `U@0ns` → `D@25ns` |
| `2` | — | `U@0ns` → `D@25ns` → `U@65ns` |
| `3` | — | `U@0ns` → `D@25ns` → `U@65ns` → `D@85ns` |
| `L` | `L@96ns` | `L@75ns` |
| `H` | `H@96ns` | `H@75ns` |

### 逐周期还原

| 周期 | 时间 | SD1 | CLK 实际波形 |
|---|---|---|---|
| 1 | 0~100ns | 槽位0 → 恒低 | 槽位0 → 恒低 |
| 2 | 100~200ns | 槽位1 → 恒高 | 槽位1 → 25ns 正脉冲（**RZ**） |
| 3 | 200~300ns | 槽位0 → 恒低 | 槽位2 → 窄脉冲+宽脉冲（3 边沿） |
| 4 | 300~400ns | 槽位1 → 恒高 | 槽位3 → 窄+宽+回落（**SBC**，4 边沿） |
| 5 | 400~500ns | L → 96ns 采样期望低 | L → 75ns 采样期望低 |
| 6 | 500~600ns | H → 96ns 采样期望高 | H → 75ns 采样期望高 |

### 官方示波器图的读法

- **绿色粗线** = 信号电平
- **上方红色数字** = 该周期用的 WFC 槽位名
- **红色双向箭头 + 数字** = CLK 的 WFC 槽位标注
- **向上小箭头** = 比较采样点
- **蓝色虚线** = 周期边界

### CLK 槽位 3 = SBC 的教科书实例

三个边沿把数据有效窗口框成 **65~85ns**，而比较点 `H@75ns` 正好落在
窗口正中，左右各留 10ns 余量。NRZ 做不到——数据在 T0 就变了，
采样沿离 T0 有多远全靠运气。

## 五、四种信号格式（RZ/RO/NRZ/SBC）与 Wave Table

### 官方出处

`2.教学课件/6.课件-数字电路模块功能介绍.pdf` 第 11 页：

> 归0（Return to Zero，**RZ**），归1（Return to One，**RO**），
> 非归0（None Return to Zero，**NRZ**）及补码环绕
> （Surrounded by Complement，**SBC**）等 Format。此外，某些 ATE 提供
> 更灵活的方式供用户定义波形格式，如在时刻点自由定义信号的升降，
> 以及它们的组合，通常称这种方式为 **Wave Table**。

同一段文字也出现在 `4课件-集成电路基础测试原理.pdf` 第 28 页。

### 加速科技不提供这四个关键字

`1.技术手册/3.ST2500简明使用教程V3.pdf` 明说 WFC 列 =
"波形格式符号，可自行命名"。所以：

| 格式 | 边沿数 | Wave Table 拼法 |
|---|---|---|
| NRZ | 1 | 1 个 Evt |
| RZ / RO | 2 | 2 个 Evt（加一个回零/回一边沿） |
| **SBC** | **3** | 3 个 Evt，**唯一能同时保 setup/hold** |

**换信号格式 = 改 `.tim` 的 WFC 槽位 Evt 定义，不是改 Pattern。**
Pattern 侧只需把引脚列填的字符换成新槽位名。

### 为什么 ATE 需要这四种

DUT 引脚有三种性质：

| 引脚性质 | 例子 | 适用格式 |
|---------|------|---------|
| 控制/选通 | CS#、OE# | RZ（高有效）/ RO（低有效） |
| 数据/地址 | DIN | **SBC** |
| 时钟 | CLK | RZ / RO |
| 普通传输 | 串行线 | NRZ |

更硬核的原因是**边沿数直接决定 ATE 时序发生器的硬件门槛**：
NRZ 只要 1 个边沿，RZ/RO 要 2 个，**SBC 要 3 个且脉冲宽度精确可控**——
所有格式里硬件要求最高。没有 SBC 就无法测有严格 setup/hold 的器件，
只能靠拉长周期间接保证，测试时间成倍增加。

**SBC 是唯一能同时保证建立时间和保持时间的格式**：把数据稳定区正好包在采样沿两侧。

### 工程实例

- HK24C02 `WFT1`(1000ns)：SCL `D@0ns,U@600ns` = **手工 RZ 脉冲**；
  SDA 240ns 驱动 / 840ns 采样 = **手工 SBC 环绕**；
  `WFT2`(5000ns) 是把周期拉长 5 倍加大 setup/hold 余量的替代手法
- ADC0832 `TS1` CLK `D@0ns,U@2000ns,D@3996ns` = NRZ 做不到的 2 边沿方波

## 六、Sequence 微指令（只管控制流，不管电平）

官方手册第 69 章有完整 20 条，工程里实际用到 9 种。

工程实际用到的：
- `nop`（29.3 万次）—— 空向量
- `[C]nop`（3.3 万次）—— 记入 Capture Mem，配 `EN_CAP_MODE`
- `repeat N`
- `loop N Label` —— **从 loop 指令的下一行循环到 Label 所在行，共 N 次**
- `stop`
- `loop_inf` —— 配合 TMU 测频 + `SetHoldExit()`（PLL 标准套路）
- `STV` —— 标记采样点
- `[C]STV`
- `Trig AWG_CH`

**`loop N Label` 语义**（易错）：loop 指令本身**不产生向量**，只标起点。
例：`adc_pat.csv` 的 `loop 100 51`、ADC0832 的 `loop 4096 adc`、
EEPROM 的 `loop 255 75`。

**`[C]` 前缀两种含义**：`[C]nop`/`[C]STV` = 记入 Capture Mem；
其它指令的 `[C]` 仅表示可被捕获。

## 七、Pattern CSV 格式

```
Label,WFT,sequence,<信号1>,<信号2>,...,<信号N>
0,TS1,nop,1,0,X,X
```

- `Label` 行号（也用作 loop 的跳转目标）
- `WFT` = `.tim` 里的 `TimingName`
- `sequence` = 微指令
- 后面各列 = 各信号的 WFC 槽位名

**最经典的坑**：同一个字符写在不同信号列含义完全不同。

以 ADC0832 `ADC_CH0.CSV` + `TS1` 为例：

| Pattern 写的 | 查到的槽位 | 实际波形 |
|---|---|---|
| `CS=1` | CS 的 WFC=1 = `U@0ns` | 恒高（片选无效） |
| `CS=0` | CS 的 WFC=0 = `D@0ns` | 恒低（片选有效） |
| `DI=1` | DI 的 WFC=1 = `U@0ns` | 恒高 |
| **`CLK=0`** | CLK 的 WFC=0 = `D@0ns` | **恒低，整个周期无时钟** |
| **`CLK=1`** | CLK 的 WFC=1 = `D@0ns,U@2000ns,D@3996ns` | **一个时钟脉冲！** |
| `DO=H` | DO 的 WFC=H = `H@2500ns` | 2500ns 采样期望高 |
| `DO=X` | DO 的 WFC=X = `X@2500ns` | 2500ns 采样不关心 |

> **同一个字符 `1`，写在 CS 列是"恒高"，写在 CLK 列却是"一个时钟脉冲"。**
> 别想当然认为「Pattern 里的 0 就是低电平」——**对时钟线不成立**。

## 八、设计检查清单

- [ ] `.tim` 每个信号的槽位覆盖了 Pattern 里用到的全部字符
- [ ] 驱动槽位：Evt 数 ≤ 4；比较槽位：只填 Evt0
- [ ] 比较时刻在"期望值确定成立"的区间内（等 DUT 输出稳定）
- [ ] **功能测试同时比较全部输出脚**（否则脚间短路/浮空测不出）
- [ ] 低有效器件：测 VOL 要让该路被选中，测 VOH 要让该路不被选中
- [ ] `.pat` 注册的每个 CSV 都存在，pattern 目录无未注册文件
- [ ] 用 `scripts/validate_project.py` 跑一遍
